# Accessibility checklist (task 061)

Rasoi is used one-handed, in a kitchen, often with something in the other hand — and sometimes at
a text size much larger than the default. This is what the build guarantees, and how it is checked.

## Automated

`RasoiUITests/AccessibilityUITests.swift` runs on every `bash scripts/verify.sh`:

| Test | What it proves |
|---|---|
| `testEveryTabRendersAtAccessibilityExtraLarge` | All five tabs render, show text and keep their tab bar at `UICTContentSizeCategoryAccessibilityXL`. |
| `testPrimaryActionsAreReachableAtLargeText` | "Generate week" and "Build list" are still tappable at accessibility XL — they live in the navigation bar or at the top of the list, not below a wall of content. |
| `testIconOnlyControlsAreLabelled` | Icon-only buttons carry a spoken label ("Add to pantry", "Previous week", "Next week", "Sort and more"). |
| `testCoverageDotsAreDescribedInWords` | Each MyPlate dot reads as "Fruit: covered" / "Fruit: not yet" rather than as an unlabelled shape. |

## By hand

- [x] **Tap targets.** `Theme.minimumTapTarget` (44 pt) and `Theme.largeTapTarget` (56 pt) are used
      for every primary action: Cook, Generate week, Build list, the three feedback buttons, the
      grocery check circle, avatar and colour pickers.
- [x] **Icon-only buttons are labelled.** Toolbar buttons (+, share, filter, week arrows) all have
      `accessibilityLabel`.
- [x] **Decorative icons are hidden or folded in.** Category glyphs, meal-type glyphs, chevrons and
      the store-kind glyph are `accessibilityHidden(true)` or combined into their row's element, so
      VoiceOver reads "Breakfast, Ragi Banana Pancakes" and not "Sunrise, Breakfast, …".
- [x] **Rows read as one thing.** Family, pantry, plan, today and snack rows use
      `accessibilityElement(children: .combine)`.
- [x] **State is spoken, not only shown.** Selected avatars and filter pills add `.isSelected`;
      a locked plan slot reads "Kept"; a favourite recipe reads "Favourite"; a checked grocery item
      says "Uncheck <item>".
- [x] **Cook mode is readable from a metre away.** Steps use `.largeTitle` in a rounded face, one
      step per screen, and the screen is kept awake while it is open.
- [x] **Dynamic Type everywhere.** Every font is a semantic style (`.body`, `.headline`, `.caption`
      …) — there is not a single fixed point size in the app.
- [x] **Colour is never the only signal.** Expiring items carry words ("use today", "2 days left")
      beside the colour; coverage dots carry a spoken label; checked items are struck through as
      well as tinted.
- [x] **Dark mode.** Every colour in `Theme` is defined as a light/dark pair.

## Known limits

- The plan grid is a vertical list of days rather than a 7×4 grid: at accessibility sizes a real
  grid would need horizontal scrolling with unreachable cells. This is the deviation recorded in
  `docs/SPEC-AUDIT.md`.
- Cook mode's page indicator is hidden; the "Step 3 of 7" text carries that information instead.
