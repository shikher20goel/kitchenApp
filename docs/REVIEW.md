# Rasoi — build review

What was built, what it does, what was fixed after looking at it running, and what is still open.
Screenshots referred to here are in `docs/screenshots/`, regenerated by
`bash scripts/screenshots.sh`.

## What Rasoi is

A private, local-first kitchen planner for one family's iPhone. Five tabs:

- **Today** — tonight's dinner with a "why this" disclosure, the rest of the day, a use-it-up
  banner, three quick snacks from the pantry, and the day's food-group dots.
- **Plan** — the week, four meals a day, generated from the pantry and what the children actually
  eat; every slot can be swapped, kept, skipped or marked eating-out, and every slot explains
  itself.
- **Pantry** — fridge, pantry and freezer, with shelf-life dates, expiring-first sorting, and
  mark-used / ran-out.
- **Shop** — the week's list grouped by store then by aisle; ticking an item puts it in the pantry
  with an expiry date.
- **More** — family, diet & kitchen, stores (with the MapKit finder), recipes, insights,
  notifications, appearance, about, export, delete all data.

Everything is on the device. The only network-capable code in the app is Apple's MapKit store
search, behind a button (`docs/PRIVACY-MAPKIT.md`, `docs/PRIVACY-AUDIT.md`).

Two further fixes came out of the same run, both real bugs rather than cosmetics:

- **Switching tabs showed stale data.** Tab views stay alive, so `.task` runs once; the Shop tab
  still showed what it had read before the week was planned. `ContentView` now reloads the tab's
  view model when the selection changes.
- **The tab view models were rebuilt on every parent body evaluation**, which made the first tap
  after launch miss. `TabModels` builds them once and hands them in.

## Deviations from the SPEC

Listed in full, with reasons, in `docs/SPEC-AUDIT.md` §Deviations: the Plan is a list of days
rather than a 7×4 grid; feedback is pushed instead of presented as a sheet; the "≤2 new recipes a
week" quota yields when the catalog offers nothing else; supermarkets claim every aisle while
speciality shops win first; allergen flags come from required ingredients only.

## Known gaps

- **Phase 2 is not built** and must not be: photo scan, LLM suggestions, barcode, sync, widgets
  (SPEC §9, §10).
- **The store finder has not been run against a live Apple Maps response** in this build — that is
  the human check in task 053.
- **Nothing has run on a physical iPhone yet** (task 066).

## Installing on the iPhone (task 066, when the phone is cabled)

```
bash scripts/configure-signing.sh free <TEAM_ID>
xcodegen generate
xcodebuild -project Rasoi.xcodeproj -scheme Rasoi -destination 'generic/platform=iOS' \
  -allowProvisioningUpdates -allowProvisioningDeviceRegistration DEVELOPMENT_TEAM=<TEAM_ID> \
  CODE_SIGN_STYLE=Automatic -derivedDataPath build/ build
xcrun devicectl list devices
xcrun devicectl device install app --device <UDID> build/Build/Products/Debug-iphoneos/Rasoi.app
```

`connected (no DDI)` from `devicectl` means Developer Mode is off on the iPhone. A free Apple team
signs for seven days, so this has to be repeated weekly. Plugging in, the Trust prompt, Developer
Mode and any keychain "Allow" are human-only steps.
