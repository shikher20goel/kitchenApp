## Buildable-System Extraction
A private, local-first SwiftUI/SwiftData iPhone app (SPEC mode, from docs/SPEC.md) for one vegetarian family of four: household + diet settings, a seeded catalog of 185 ingredients and 51 kid-tested vegetarian recipes, pantry tracking with shelf life, a deterministic weekly meal planner that learns from per-child meal feedback, a grocery list grouped by store that restocks the pantry when checked, a MapKit store finder, MyPlate-style coverage dots, local notifications. No AI, no photo recognition, no sync in v1 (Phase 2).

## Architecture Decision
- Stack: SwiftUI + SwiftData + MapKit + UserNotifications, iOS 26, XcodeGen-generated project, zero dependencies — identical to North so the verify/install pipeline and skills carry over unchanged.
- Diagram:
```
Views (5 tabs) → ViewModels (per feature) → Engines (pure Swift: AgeBand, DietFilter, KidScore, MealPlanner,
  GroceryBuilder, PantryDepletion, Units, ShelfLife, NutritionCoverage, QuickSnacks, Scaling)
                                          → SwiftData (HouseholdMember, DietProfile, Store, Ingredient, PantryItem,
                                             Recipe, MealPlan/Slot/Feedback, GroceryList/Item, AppSettings)
Services: SeedImporter (bundled JSON) · StoreFinder (MapKit, the ONLY network path) · NotificationScheduler · Exporter
```
- Data model: SPEC §3.
- Verification strategy: TDD pairs (tests task precedes implementation task) for every engine and view model; UI tests per tab; `bash scripts/verify.sh` = xcodegen → build → full XCTest suite on an auto-detected simulator; privacy audit script; simulator smoke-run with screenshots; HUMAN gates for seed content, copy, MapKit privacy, final install.
- Verify command: `bash scripts/verify.sh` (`--unit`, `--build-only`, or `RasoiTests/SomeTests` to scope).
- External boundaries never crossed autonomously: see prd.json forbidden_autonomous_actions.
